# NPC services: shops and refining from the NPC's dialogue

In the client's data a merchant or a smith NPC says one line and offers nothing: its `DialogueConfig` is a single row, and
the data has no NPC to shop link besides the Kafra shops. The client does have the services (the Shop menu, the equipment
panel) and the server sells and refines, so the client hook `NpcShops` adds the missing dialogue options.

## What gets what

The table is `src/Ro3Emu.ClientHooks/NpcServiceTable.cs`; `NpcServiceTableTests` checks it against `data/config`.

| NPC (id) | Option | Opens |
|---|---|---|
| Item Merchant (100019, 100143, 100144, 100170, 100311) | Open Shop | Supply Shop 140 (function 70105) |
| Every other seller (36 NPCs, below) | Open Shop | Supply Shop 140, the default |
| Pet Merchant (100064, 100145, 100166, 200009) | Open Shop | Pet Shop 210 (70113) |
| Headwear Merchant (400051) | Open Shop | Appearance Shop, headwear class 50204 (70505) |
| Stylist (100323) | Open Shop | Appearance Shop, hairstyle class 50203 (70504) |
| Antonio (100163), Hollgrehenn (200007), Leavren (100152), Sebuyalian (100164) | Refine | Equipment panel, refine page (function 8) |
| Ariel (100049, 200012) | Wardrobe | The Wardrobe panel (function 32); her line is about the Wardrobe |
| Novice Guildmaster (100045), Promoter (100075) | Guild | The Guild panel (function 13); both say they recruit for a guild |

The other sellers are the NPCs named Vendor (3), Food Vendor, Map Vendor, Merchant (7), Food, Fruit (2), Milk, Shrimp, Trade, Resting,
Sighing, Foreign and Collectibles (2) Merchant, Merchant for Hire, Shop Clerk, Gift Merchant, Jewelry Merchant (2), Café Server, and
the NPCs whose line says they sell (Butcher, Flower Girl, Granny Broom, Buddy, Daisha, Seultae, Traveler from Afar). They all
get the consumables shop: no other shop is clearly more fitting for a gift or a gem, and its currency and panel are the ones the
Shop menu already uses. A dialogue of two or three lines gets the options after its last line. The NPCs that run job, class or
event business (the mentors, the Merchant Mentor, the voting campaigners, caravan members, the exchange NPCs Miss Smile, Netvia
and Jade, the inn staff) are not sellers and are left alone; `NpcServiceTableTests` fails if an NPC named Vendor or Merchant is
neither in the table nor a listed exception.

Every row is followed by "Leave". The option texts are the client's own (`Open Shop`, `Leave`, the name of function 8).
The actions are the client's own too: `OpenFunctionUI` (25) with the shop parameters (shop type, shop id, class id, as
`UI_Sys_ShopPanelCtrl.OnInitOpenParams` reads them) or with `UI_Sys_StrengthenPanel` and page 2, then `CloseUI` (8) of the dialogue.
Because the call goes through `OpenFunctionUI`, the client still checks the function's open condition: shops need level 10,
refining level 42, and a character below that sees the client's own "not unlocked" tip. Nothing is unlocked by the hook.
Leavren and Sebuyalian speak of "Enhance"; that function (9) is closed in the data (level 9999), so they open refining.

## Every NPC, and what was decided

[The catalog](npc-services-catalog.md) lists all 1252 NPCs of the data that have an interaction, generated by
`tools/npc-catalog/npc_catalog.py`: 55 get a service, 62 have options of their own and are not touched, 322 only chat and are left
as they are (with the reason for the ones whose role looked like a service but is not one this client and server can offer),
770 use the client's own actions (portals, gathering, vehicles, event objects), 2 have a dialogue plus an own action and 41
name an interaction the data does not have. Two rules decide it:

- A service is added only where the NPC's name or line clearly names it **and** the client has a panel for it that an NPC action can
  open (`OpenFunctionUI` with the panel the main menu opens, with no initial data or with parameters made only of text) **and** the
  server handles that system. The server has no per-NPC services: the shops, refining, the Wardrobe and guilds work from their
  panels, so an option is only a second way in.
- A chatter-only NPC is never assumed to be missing something: quest options are added at run time from the player's running tasks
  (`LC_TaskHelper.GetCurNpcTaskDialogueInfos`), so it may well be a quest NPC.

Not offered, and why: the Life Skill panel (the menu opens it with a table, `iOpenType`, that an NPC action cannot pass), the Codex
(how its panel is opened was not found), the airships, inns, arena, weddings, repairs and the exchange NPCs (no function in the data,
no server feature). `NpcServiceTableTests` fails if a Vendor or Merchant is neither in the table nor an exception.

## How the rows get into the client

`NpcShops.Inject` appends the rows to the dialogue's list in `m_kCFG_DialogueConfig` after the dialogue's last row, where
`Lua_CFG_DialogueConfig.GetOptionConfigs` looks for options. It runs after every `ReLoadAllCfg` (the season switch at login
reloads all configs) and in `PassChallenges`' periodic check, and extends a dialogue only while it still has the number of rows the
table gives it, so it never adds twice. A relog therefore gets the options again.

**Every field of the row must be written.** The client's own rows get the fields they do not list (`_iCondition` 0, `_iType` 0,
empty strings) from a shared defaults table; a plain table has none, and the dialogue panel drops an option whose
`_iCondition` is not 0 (`UI_Sys_NpcDialogPanelCtrl.RefreshOptions` asks `LC_ConditionManager` about `nil`, which answers false and
logs `ProcessCondition Invalid iConditionId null`). Release 1.3.3 left them out and no option showed; 1.3.4 writes all fifteen.

## The Item Merchant of the shared dialogue

Eight NPCs share interaction 10002301 (one line of unrelated chatter), Item Merchant 100311 among them. The data holds an unused
stub of its own (interaction and dialogue 10031101, one row without text). The hook gives the stub the line the other Item Merchants
say plus the options, and points the NPC's `_iInteractID` at it. This is the one part that could not be checked against the
client's code: the log line names it ("Item Merchant 100311 (own dialogue)") when the hook applied it, and only a visit to that NPC
shows whether the client took it.

## Checking in game

`Player.log` has `[Ro3Emu.NpcShops] service options added to N NPC dialogues: ...` after login (and again after a config reload),
and no `ProcessCondition Invalid iConditionId null` when an NPC is opened.
